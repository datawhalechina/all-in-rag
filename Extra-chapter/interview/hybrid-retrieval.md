# 混合检索面试题

## Q1. 稀疏检索和稠密检索分别擅长什么？

**难度：** 基础

### 考察点

- 两类检索表示及其互补性。

### 参考答案

- 稀疏检索以词项匹配为核心，例如 BM25，擅长专有名词、编号、错误码和原文关键词，结果也较容易解释。
- 稠密检索使用嵌入向量表达语义，能召回措辞不同但含义接近的内容，对同义表达和自然语言问题更友好。
- 稀疏检索可能漏掉无词面重合的相关内容；稠密检索可能弱化精确词项，并受嵌入模型领域适配影响。二者没有绝对优劣。

### 常见误区

- 认为使用语义向量后关键词检索就没有价值；实体名、型号和代码等查询往往仍依赖精确词项。

### 延伸追问

- 哪些查询特征适合提高稀疏检索结果的权重？

## Q2. 为什么 RAG 系统要使用混合检索？

**难度：** 基础

### 考察点

- 多路召回解决的单路检索局限。

### 参考答案

- 用户查询可能同时包含语义意图和必须精确匹配的实体。单一检索器难以稳定覆盖所有查询类型。
- 混合检索分别运行稀疏和稠密召回，再融合候选与排名，可在一条查询中利用词面相关性和语义相关性。
- 它通常提高召回稳健性，但会增加索引、查询、融合与调参成本；收益应通过分查询类型的评估验证。

### 常见误区

- 认为把两路结果拼接起来就完成了混合检索；还需要去重、融合排序，并控制各路候选贡献。

### 延伸追问

- 如何判断混合检索相对单路检索的收益来自哪些查询？

## Q3. Elasticsearch 的倒排索引和向量检索分别如何工作？

**难度：** 基础

### 考察点

- ES 文本检索、向量检索及二者组合的核心数据结构与流程。

### 参考答案

- 文本写入 ES 时，analyzer 经过字符过滤、分词和 token 过滤得到词项；倒排索引保存“词项 -> 包含它的文档及词频、位置等信息”。查询也要经过兼容的分析链，再由 BM25 等算法根据词频、文档频率和文档长度排序。
- 向量检索先把文档和查询编码为同一空间中的 `dense_vector`。精确 kNN 会扫描候选向量；近似 kNN 通常通过 HNSW 图导航，只访问部分节点，以少量召回损失换取速度。
- 混合检索让 BM25 与 kNN 各自召回候选，按统一文档 ID 去重，再用 RRF 或经过校准的分数融合排序；必要时使用 Cross-Encoder 精排。
- 过滤条件应在两路保持一致。权限属于硬约束，不能只在融合后随意丢弃，否则候选不足时可能产生越权或结果数量不稳定。

### 常见误区

- 认为倒排索引存的是“文档 -> 词项”，或把 HNSW 说成精确遍历全部向量；二者分别是词项到文档的映射和近似图搜索。

### 延伸追问

- 索引分析器和查询分析器不一致会怎样影响 BM25 召回？

## Q4. 混合检索中的权重误差如何产生，又该如何校准？

**难度：** 进阶

### 考察点

- 异构分数不可比、权重过拟合、动态路由及校准方法。

### 参考答案

- BM25 与向量相似度来自不同公式，数值范围、分布和查询间稳定性都不同；有的系统返回相似度，有的返回距离，优劣方向也可能相反。
- 直接相加会让数值尺度较大的一路主导排序；固定权重还可能只适合调参集，例如实体/编号查询偏 BM25，自然语言改写查询偏向量检索。
- 首先保留 BM25、向量和融合后的分数、名次与命中标签，排查分数方向、归一化范围、候选深度、过滤条件和文档去重是否一致。不要一看到结果差就只调权重。
- 无监督基线可采用 RRF，避开原始分数尺度。需要加权分数时，应在独立验证集上使用稳定的归一化或校准方法学习权重，并在未参与调参的测试集上报告结果，防止过拟合。
- 生产中可按查询类型选择权重或路由，但规则必须由分桶评估支持，并设置保守回退。上线后监控各路贡献率、零结果率、排序指标和分数分布漂移。

### 常见误区

- 在同一批测试数据上反复调权重再报告最高分，或者把每路除以当前最大值就视为完成校准；两者都会高估泛化效果。

### 延伸追问

- 如何通过消融实验判断误差来自单路召回、候选深度、融合权重还是后续重排？

## Q5. RRF 如何融合多路检索结果？参数 k 有什么影响？

**难度：** 进阶

### 考察点

- Reciprocal Rank Fusion 的计算逻辑和适用边界。

### 参考答案

- RRF 不比较原始分数，而是对文档在每一路的名次 `rank` 累加 `1 / (k + rank)`；同时在多路靠前的文档会得到更高融合分数。
- 参数 `k` 平滑名次差异。较小的 `k` 更强调头部名次差距；较大的 `k` 让相邻名次贡献更接近。
- RRF 对异构分数尺度稳健且无需复杂标定，但会丢弃原始分数置信信息，也不能自动保证每一路质量相同。
- 各路候选深度过小会让融合缺少交集，候选过深则增加延迟和噪声，因此 `k` 与候选深度都应在验证集上调整。

### 常见误区

- 把 RRF 的 `k` 当作最终返回文档数量；它是排名公式中的平滑常数，不是 Top-K。
