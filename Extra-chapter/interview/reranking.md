# 重排面试题

## Q1. RAG 中的召回和重排分别负责什么？

**难度：** 基础

### 考察点

- 两阶段检索架构的职责划分。

### 参考答案

- 召回阶段从大规模语料中快速找出一批可能相关的候选，首要目标是不要漏掉相关证据，通常使用稀疏、稠密或混合检索。
- 重排阶段在较小候选集上使用更精细的相关性模型重新排序，首要目标是把真正有用的证据移到前面。
- 重排只能调整已经召回的候选，无法找回召回阶段遗漏的文档，因此两阶段需要分别评估和调优。

### 常见误区

- 认为加入强重排器就能弥补召回缺失；相关文档不在候选集中时，重排器没有处理机会。

## Q2. 重排器如何判断候选内容对当前问题更重要？

**难度：** 基础

### 考察点

- 重排分数的含义、常见实现以及业务重要性与查询相关性的区别。

### 参考答案

- 重排器通常判断的不是内容的全局“重要性”，而是候选相对当前查询的相关性或回答效用。Cross-Encoder 会联合读取查询与候选，输出相关性分数；ColBERT 使用 token 级后期交互；LLM 重排可依据自然语言评分规则比较候选。
- 模型一般从人工或构造的相关/不相关样本、排序对或列表中学习。分数表示模型偏好，不天然等于概率，也不能跨模型直接比较；阈值应在领域验证集上校准。
- 生产系统还可加入来源可信度、时效、权限、文档类型和去重/多样性等信号。权限必须作为硬过滤，不能让模型分数覆盖；可信度等业务信号则应与语义相关性分开记录并通过可解释规则融合。
- 最终按上下文 token 预算选择候选，并使用 nDCG、MRR、Precision@K 等排序指标及端到端答案质量验证收益。

### 常见误区

- 把重排分数当作客观“重要性”，或直接用它代替权限、真实性和时效校验。

### 延伸追问

## Q3. Bi-Encoder 与 Cross-Encoder 在检索中的区别是什么？

**难度：** 基础

### 考察点

- 独立编码与联合编码的质量/效率差异。

### 参考答案

- Bi-Encoder 分别编码查询和文档，文档向量可离线计算并建立 ANN 索引，适合大规模快速召回。
- Cross-Encoder 将查询和每个候选文档共同输入模型，让 token 之间充分交互后输出相关性分数，通常更精细，但每个查询-文档对都要在线推理。
- 常见组合是 Bi-Encoder 先召回候选，Cross-Encoder 再重排，以候选规模控制计算成本。

### 常见误区

- 认为 Cross-Encoder 可以像文档向量一样预计算后直接做全库 ANN；它的分数依赖当前查询与文档的联合输入。

## Q4. 重排候选集大小如何影响效果和延迟？

**难度：** 进阶

### 考察点

- 候选深度在召回上限、计算成本和噪声之间的权衡。

### 参考答案

- 增大候选集能提高相关文档进入重排阶段的机会，为最终排序提供更高召回上限。
- 候选越多，重排推理次数、批处理成本和延迟越高；大量弱相关候选还可能增加排序难度。
- 候选过少则即使重排器很强，也可能因关键文档未进入候选而失败。
- 应在代表性查询上绘制候选深度对应的 Recall@K、重排后指标、P95 延迟和成本曲线，选择收益开始饱和的位置，并与最终上下文数量分开配置。

### 常见误区

- 把“召回候选数”“重排候选数”和“送入生成模型的文档数”设置成同一个值。

## Q5. Cross-Encoder、ColBERT 和 LLM 重排应如何选择？

**难度：** 进阶

### 考察点

- 不同交互粒度重排方法的能力与工程代价。

### 参考答案

- Cross-Encoder 联合编码查询与候选，相关性建模充分，适合中小候选集的高质量精排，但逐对推理成本较高。
- ColBERT 保留查询和文档的 token 级向量，通过后期交互计算匹配，在细粒度相关性和可复用文档表示之间折中，但索引与部署更复杂。
- LLM 重排可使用自然语言指令、列表比较和更强推理能力，适合复杂相关性标准；代价通常是更高延迟、成本，以及输出稳定性和位置偏差风险。
- 应根据领域评估效果、候选规模、延迟预算、部署资源和可解释性选择；也可以采用轻量重排后再对极少候选使用更昂贵模型的级联方案。

### 常见误区

- 仅按模型参数规模判断重排质量，忽略任务适配、输入截断、候选顺序和推理成本。
