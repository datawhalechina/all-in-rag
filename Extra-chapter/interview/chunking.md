# 分块面试题

## Q1. RAG 如何缓解 LLM 上下文窗口有限的问题？

**难度：** 基础

### 考察点

- RAG 对上下文限制的作用边界，以及检索、分块和上下文组装的配合。

### 参考答案

- RAG 不会扩大模型的上下文窗口，而是先把长文档切成可检索单元，再只选取与当前问题相关的少量证据放入窗口，提高有限 token 的有效信息密度。
- 在线链路通常是“召回较多候选 -> 重排与去重 -> 按 token 预算组装上下文”。必要时可压缩候选内容，或采用“小块检索、大块生成”补回父段落和相邻上下文。
- 系统还应为系统提示、对话历史、问题和模型输出预留 token，不能让检索片段占满窗口；超出预算时应按相关性和证据互补性选择，而不是简单截断。
- 对需要跨文档、多跳或全文总结的问题，一次局部检索可能不够，可采用查询分解、分层检索或迭代检索，但会增加延迟和成本。

### 常见误区

- 说 RAG “解决”或“突破”了上下文上限；它只是选择更相关的内容进入固定窗口，也可能漏召回关键证据。

### 延伸追问

- 当召回内容仍超过 token 预算时，应如何在相关性、证据完整性和多样性之间取舍？

## Q2. 文本块过大或过小分别会带来什么问题？

**难度：** 基础

### 考察点

- 分块粒度对检索质量和生成上下文的影响。

### 参考答案

- 块过大时，一个向量可能混合多个主题，使局部信息的语义特征被稀释；召回后还会占用更多上下文窗口，降低有效信息密度。
- 块过小时，句子、定义与论据容易被拆开，检索结果缺少回答问题所需的完整语境；块数量增加也会扩大索引与检索开销。
- 合理粒度取决于文档结构、问题跨度、嵌入模型能力和生成模型的上下文预算，应通过代表性查询评估，而不是只选一个固定字符数。

### 常见误区

- 只根据生成模型的最大上下文长度设置块大小，忽略嵌入模型限制和实际问题需要的证据跨度。

### 延伸追问

- 评估不同块大小时，除了答案质量还应观察哪些指标？

## Q3. 分块重叠（chunk overlap）有什么作用和代价？

**难度：** 基础

### 考察点

- 重叠窗口解决的问题及其资源代价。

### 参考答案

- 重叠会在相邻块中保留一部分共同文本，降低关键句、指代关系或段落过渡恰好落在边界时的信息损失。
- 它能提高边界附近证据被完整召回的机会，但不能修复所有不合理切分，也不能替代结构感知分块。
- 重叠越大，重复文本、嵌入计算、存储占用和重复召回越多；进入生成上下文前还可能需要去重或合并相邻块。

### 常见误区

- 把重叠比例当作越大越好的召回参数；过度重叠可能让 Top-K 被内容近似相同的块占满。

### 延伸追问

- 如何避免相邻重复块挤占有限的生成上下文？

## Q4. 固定大小、递归字符、语义和结构感知分块有什么区别？

**难度：** 进阶

### 考察点

- 常见分块策略的原理、成本和适用边界。

### 参考答案

- 固定大小分块按字符或 token 窗口切分，简单、稳定且易控制成本，但可能破坏句子和章节边界。
- 递归字符分块按段落、换行、句子等分隔符逐级尝试，在满足大小约束的同时尽量保留自然边界，是通用文本的常见基线。
- 语义分块依据句子嵌入或语义变化确定边界，更可能保持主题一致，但需要额外模型计算，阈值也会影响块大小稳定性。
- 结构感知分块利用 Markdown 标题、HTML 元素、表格、代码函数等显式结构，适合结构可靠的文档；解析质量差时效果也会受影响。

### 常见误区

- 认为语义分块在任何数据上都优于规则分块；它的额外复杂度必须通过目标查询上的评估证明有收益。

### 延伸追问

- 对包含标题、正文、表格和代码的混合文档，你会如何组合这些策略？

## Q5. 如何根据文档和检索目标选择分块策略？

**难度：** 进阶

### 考察点

- 将数据特征、问题类型与评估方法结合起来选择策略。

### 参考答案

- 先分析文档：是否有可靠标题层级、表格或代码结构，段落长度是否稳定，答案通常分布在一句、一个段落还是跨多个章节。
- 再分析查询：事实型问题适合较精确的局部证据；总结或多跳问题需要更宽上下文，或采用小块检索后扩展父块、相邻块的方式。
- 以简单策略作为基线，在同一代表性评估集上比较 Recall@K、上下文相关性、答案质量、索引规模和延迟，而不是凭直觉选择复杂方案。
- 块中应保留标题、来源、页码等元数据，使检索过滤、上下文扩展和引用能够使用原始结构。

### 常见误区

- 只调 `chunk_size`，却不检查文档解析是否正确，也不保留块与原文结构的映射。
